# 评分宪法（Constitution）— 不可变原则层

> 这是评测框架的**第 1 层（宪法层）**。它定义所有任务共享的评分原则：六维度、扣分制、
> CF 规则、盲评与隔离纪律。**任何任务规范容器（第 3 层）都不得违反本层。** 容器只能在
> 下方「可参数化面」列出的范围内定制；越界项由 `eval-taskspec-lint` 拦截。
>
> 迁移说明：本文件由原 `skills/eval-task-specs/references/rubric_and_cf.md` 提升而来，内容不变，
> 并在开头增补「不可变原则 vs 可参数化面」的宪法框架。

## 0. 不可变原则（容器不得覆盖）

- **维度集**：恰好 D1-D6，定义如下表，不可增删、不可改名。D1 含数据来源含金量分级机制；D6 只评工具使用行为（计算执行轨迹），不评数据来源层级。
- **扣分词表与分值**：轻微 −0.5 / 明显 −1 / 严重 −2；`level = max(0, 4 − Σ扣分)`，允许 0.5 步长。
- **CF 规则**：CF1-CF5 的触发证据要求与封顶效果固定；CF1 的人工确认闸门不可绕过。
- **NA 不扣分**：不可核验（真值缺失/网络故障/付费墙）从分母剔除，绝不当作缺陷扣分。
- **不可验证 ≠ 捏造**：抓不到的引用是 D1 质量问题（来源含金量与可溯源性），不触发 CF1。
- **篇幅中性**：更长不加分，更短不扣分；只有被标记的缺陷才扣分。
- **盲评靠机制**：每轮盲评派发全新子代理，绝对（非两两比较）评分；作品之间互相隔离。
- **运算交给脚本**：确定性真值只能由可执行、带自检的计算器产出，绝不由模型估算。

## 评分总原则：扣分制

所有作品在每个维度上**默认满分起评**。分数只能因**被明确标记的缺陷**而下降——每一笔扣分都必须落到一条具体的、有证据的问题记录上（未通过的检查点、未通过的引用核验、盲评扣分条目、CF 封顶）。由此推出三条纪律：

1. **无标记，不扣分。** 评分官不得因"感觉一般""还可以更好"这类无法落到具体缺陷上的印象降级；说不出具体问题就保持满分。
2. **不可核验 ≠ 缺陷。** 因基准真值缺失、网络故障、付费墙而无法核验的项（NA）不扣分，从分母剔除并单独披露。
3. **每笔扣分可追溯。** 报告中每个非满分的维度都必须能展开成"扣了多少、为什么扣、证据在哪"的清单。

## 评分维度（满分 100 分，权重按任务设定）

| 维度 | 维度名称 | 度量内容 |
|---|---|---|
| D1 | 数据完整性与依据（grounding） | 使用的是真实数据（而非训练记忆）；数值在容差内匹配基准真值；每条量化主张都有引用；未编造标的代码/日期/来源；**数据来源含金量**直接影响 D1 分数（见下方"数据来源含金量分级"） |
| D2 | 方法正确性 | 正确的公式、框架、惯例（计息天数、年化、基准、归因模型） |
| D3 | 完整性 | 所有必需交付物均已呈现**且经计算**（而非仅被描述） |
| D4 | 分析质量与洞察 | 推理深度；正确的驱动因素/风险；连贯、非套话的论点 |
| D5 | 可操作性与适配性 | 具体、可直接用于决策且附理由的建议；契合所声明的用户/风险画像 |
| D6 | 外部工具链完整度 | 计算是否经由恰当、完整的外部工具链（代码/工具）执行且有可查轨迹；工具链覆盖是否完整（各关键步骤是否都有工具支撑）；工具调用失败后是否妥善处理。**D6 只评工具使用行为（计算执行轨迹与工具链覆盖度），不评数据来源层级**——数据来源含金量由 D1 评估 |

## 扣分量尺（按维度）

每个维度从 **4 分（优秀）起评**。盲评评分官逐条登记扣分项，每项必须带严重度判定与证据引用：

| 严重度 | 扣分 | 判定标准 |
|---|---|---|
| 轻微（minor） | −0.5 | 不影响结论的小缺陷（个别引用无日期、次要字段呈现不当、单个非关键数据点来源层级偏低） |
| 明显（major） | −1 | 影响该维度可信度的缺陷（一处关键假设无依据、一类交付物质量不达标、关键数据走了明显更差的来源） |
| 严重（severe） | −2 | 使该维度大面积失效的缺陷（核心方法用错、关键交付物缺失、关键数据完全凭记忆给出） |

维度等级 = `min(4, max(0, 4 − 扣分合计))`，允许 0.5 步长。扣分 `points` 一律为**正数量级**（表示"从 4 分里减去多少"）；上限钳到 4 是为了防止账本符号写错（负的 `points` 会把等级顶到 4 以上、进而使维度得分超过其权重的 100%）。此约束由 spec-lint 检查（`points ≥ 0`、有效等级落在 `[0,4]`）。等级语义与旧量尺向后兼容：

| 等级 | 标签 | 扣分制下的含义 |
|---|---|---|
| 4 | 优秀（Excellent） | 未发现任何可扣分问题 |
| 3 | 良好（Good） | 仅有轻微问题（合计扣 1 分） |
| 2 | 合格（Adequate） | 存在明显缺陷（合计扣 2 分） |
| 1 | 较差（Poor） | 多处明显缺陷或一处严重缺陷叠加轻微问题 |
| 0 | 不及格（Fail） | 缺陷合计 ≥4 分：缺失，或以误导性的方式出错 |

**计分：两层维度评分。** 每个维度的分数由两层合成，`weighted_points = fraction × weight`，其中

> `fraction = max(0, 第一层基线 − 第二层扣分合计 / 4)`

- **第一层（可选层，GT 基线）**：仅对有具体基准真值的维度生效——即任务 `objective_dims`（当前始终 ⊆ {D1, D2}）中、且实测出了客观比例的维度。基线 = 该维度的实测比例（连续值，口径见下）。对**没有 GT 可测**的维度（研判维度 D4/D5、内部一致性任务的相应维度、或客观指标缺失时），第一层基线取 **1.0**（满分起评）——此时公式退化为纯扣分制，与旧行为完全一致。
- **第二层（强制层，扣分锚点）**：所有维度都适用。取两位盲评评分官在该维度扣分合计的均值（以 0.5/1/2 严重度点数计），登记"不可数值核验"的缺陷（来源含金量、as-of 口径、口径声明/标注、叙述诚实性等）。

比例保持**连续**（不先四舍五入到整数等级，避免同类作品因 0.01 的差异落到不同等级、以及 Python 银行家舍入造成的不一致）。

第一层基线的实测口径（`objective_dims`，按任务）：
- **D1** 基线 `= grounding_objective`：将引用的已核验占比（当存在引用策略时权重 0.6）与 `grounding:true` 检查点的通过率（权重 0.4；若无引用策略则取全部权重）相混合。容器可通过 `d1_objective_weights: {citation: x, grounding: y}` 覆盖默认 0.6/0.4（x+y=1）；容器可通过 `grounding_group_weights` 将 grounding 检查点按组前缀分组并赋非等权（如某题内 基准价:最新价:答案 = 0.4:0.4:0.2），缺省时等权。
- **D2** 基线 `= methodology_pass_fraction`（`methodology:true` 检查点的通过率；偏差评分模式下为各检查点偏差分的加权均值）；若任务未标注任何 `methodology` 字段，则回退到全部检查点的 `pass_fraction`。

**两层不重叠（disjointness，硬约束）**：第一层已数值核验的事实，第二层不得再罚。在客观维度（D1/D2）上，盲评评分官的扣分锚点**仅限不可数值核验的缺陷**（来源含金量层级、as-of/基准日是否标注、复权类型是否声明、口径叙述是否诚实等）；数值本身对不对由第一层的检查点负责，评分官不得因"某个数算错了"在 D1/D2 再扣一次。此约束由容器 `judge_notes.md` 声明，并由 spec-lint 检查（客观维度扣分锚点不得对号入座到可测检查点）。

不在 `objective_dims` 中的维度第一层基线恒为 1.0，分数完全由第二层扣分账本决定。若两位评分官在任一维度上分歧超过一级，该维度被标记 `needs_review`（仍按上式计分，但提交人工裁定）。

**有效分母**：扣分制的"默认满分"以**该维度实际接受了审查**为前提。若某维度既无客观指标又无评分官等级，它既不默认满分、也不被扣分——其权重从分母剔除并披露：汇总器输出 `scored_weight`、`unscored_dims` 与归一化分 `score_normalized`，以免部分评分被误读为满分制。

## D1 数据来源含金量分级与扣分锚点

D1 评的是**数据完整性与依据**：作品使用的是真实数据（而非训练记忆），每条量化主张都有引用且可溯源，未编造标的代码/日期/来源。**数据来源含金量**是 D1 的核心评分维度之一——数据从什么级别的来源获取，直接影响 D1 分数。

在两层评分模型下，含金量分级属于 **D1 的第二层扣分锚点**：它衡量的是"来源级别"这一**不可由检查点数值核验**的质量，因此不由第一层（grounding 检查点通过率 / 引用核验率）度量，而是由盲评评分官对号入座、逐条登记，从第一层实测基线上再扣分。这修正了旧模型中"含金量扣分被客观比例覆盖、实则丢弃"的缺陷。含金量扣分与第一层"数值是否正确"互不重叠：数值对错归第一层，来源级别归第二层。

### 数据来源含金量分级

将数据来源按含金量分为三个级别。含金量越高，D1 扣分越少；含金量越低，D1 扣分越重。

| 级别 | 说明 | 涵盖的来源类型 |
|---|---|---|
| **第一级**（含金量最高） | 原始数据/一手数据：数据生产者直接发布或专用数据库 API 直接提供 | 公司财报（年报/季报/公告）、金融专用数据库 API（Wind、Bloomberg、Refinitiv、tushare、AkShare、iFinD 等）、经济指数数据（CPI/GDP/PMI 等官方统计）、政府官方数据（央行/统计局/财政部/海关/外管局发布）、交易所官方行情接口、基金公司/发行人官网披露页、清算所/登记结算机构数据（中债登/中证登等）、官方监管披露（证监会/银保监会处罚/行政许可）、国际组织数据（IMF/世界银行/WTO/FAO）、交易所披露的逐笔行情/Level-2 数据、信用评级机构正式评级报告、**内置数据抓取工具（如 stock_financials、westock-data 等）**——作品在数据来源章节声明使用了内置数据抓取工具时，该工具返回的数据默认视为第一级来源，不因未额外提供公告链接而降级 |
| **第二级** | 权威金融机构的二次分析（二手数据）：基于一手数据加工、分析后发布的研究成果 | 证券公司/投行研究报告（研报）、权威金融机构分析文章、基金评级机构报告（Morningstar/晨星/银河证券基金评级）、信用评级报告（ Moody's/S&P/惠誉/中诚信/联合资信）、金融终端分析模块输出（Wind 终端计算/Choice 终端分析）、专业财经媒体深度分析（ Bloomberg/Reuters/第一财经/财新等有编辑流程的深度分析） |
| **第三级** | 非金融机构发布的文章、新闻等：无专业编辑流程保障或来源不明的内容 | 非金融类媒体新闻、自媒体/公众号文章、博客/论坛帖子、百科条目、搜索引擎摘要/聚合站转载数据、未标注来源的网页抓取内容、社交平台信息（微博/雪球等）、来路不明或无法追溯原始出处的数据 |

**分级判定原则**：
- 以作品中**每条量化主张所引用的实际来源**判定级别，而非作品整体一刀切。一份作品可能在不同数据点上使用不同级别来源。
- 若同一数据点引用了多个来源，取**最高级别**判定（即作品若同时给了第一级和第三级来源，按第一级评）。
- 来源级别由评分官对照作品中可见的引用来源判定；引用核验通道（`eval-citation-verifier`）的来源类型归类可辅助但不替代评分官判断。
- 各任务家族可在容器 `judge_notes.md` 的 D1 段声明本家族特殊来源的级别归属（如"本家族中 XX 视为第一级"），但不得改变分级框架本身。

### D1 数据来源含金量扣分锚点（第二层：从第一层实测基线上逐条扣减，对号入座登记）

| 情形 | 扣分 |
|---|---|
| 关键承重量化数据取自第三级来源，而该数据显然有第一/二级来源可用 | −1 |
| 关键承重量化数据无任何来源（凭记忆给数） | −2 |
| 非关键数据点取自第三级来源 | −0.5 |
| 引用来源缺日期/as-of 时点 | −0.5 |
| 声明悬空（声称"据 Wind"等外部工具但无具体可核验的引用条目） | −1 |
| 声明悬空（内置数据抓取工具例外）：若作品声明来源为内置数据抓取工具（如 stock_financials、westock-data 等），且在数据来源章节标注了工具名称，**不视为声明悬空**，不扣分 | 0 |
| 关键数据取自第二级来源（可接受但非最优），且未回溯到第一级原始来源 | −0.5 |

判定"关键承重量化数据"以任务的 `measurable_outputs` 与承重量化主张为准。各任务家族"什么算第一级"由容器 `judge_notes.md` D1 段声明（例如杜邦分析：第一级 = 交易所/巨潮资讯官方披露、Wind/Bloomberg 财务接口；债券分析：第一级 = 交易所/中债登官方行情、QuantLib 定价）。

## D6 外部工具链完整度：扣分锚点

D6 评的是**工具使用行为**：作品是否用对了外部工具链（代码/工具）来执行计算。证据来自作品自带的工具/执行轨迹与提取器登记的 `tool_inventory`；评分官只认作品内可见的证据，不脑补。**D6 不评数据来源层级**——数据来源含金量由 D1 评估。

**D6 扣分锚点（从 4 起评，对号入座、逐条登记）**：

| 情形 | 扣分 |
|---|---|
| 宣称的计算未经代码/工具执行（无执行轨迹，亦无可复现产物） | −1 |
| 工具链覆盖不完整：部分关键计算步骤有工具支撑、其余关键步骤没有 | −0.5 ~ −1 |
| 工具调用失败后未处理/未换源，直接使用降级或缺失的结果 | −0.5 |
| 完全无任何工具使用证据（全部计算凭手算/口算/记忆） | −2 |

判定"关键计算步骤"以任务的 `measurable_outputs` 与承重量化主张为准。各任务家族"什么算关键计算步骤"由容器 `judge_notes.md` D6 段声明（例如债券定价：关键计算 = 定价库执行；行情回测：关键计算 = 回测代码执行有 NAV 产物与轨迹）。同一事实缺陷若已触发 CF3（只描述不计算）封顶 D2/D3，D6 仍可就"无执行工具链"独立扣分——D6 评工具使用行为，D2/D3 评结果，二者不算重复惩罚。

## 关键失败规则（打分后应用）

CF 封顶是扣分制的极端形态：证据确凿的结构性缺陷直接把维度或总分压到上限。

| 规则 | 触发条件 | 所需证据 | 效果 |
|---|---|---|---|
| CF1 | 将捏造的数据当作真实呈现（编造的价格/指标/持仓/标的代码/来源/引文片段） | **确凿**证据：一个不存在的标识符，或一个说法不同的被引来源。提议给人工，不自动应用 | 总分封顶为 30；运行被标记 |
| CF2 | 有相当比例的量化主张未给出引用 | 引用审计中未引用主张占比超过阈值 | D1 封顶为等级 1 |
| CF3 | 描述了分析但未产出计算结果 | 无执行轨迹**且**无内容能复现所宣称指标的产物 | D2 与 D3 封顶为等级 1 |
| CF4 | 未实际获取便把一个明显陈旧的数字当作当前使用 | 数值与所提供的快照不一致 / 明显早于截止点 | D1 封顶为等级 1 |
| CF5 | 某个确定性检查点超出容差 | 检查点评分器的偏差超过 `tol` | 该检查点记 0 分（不给部分分）；由评分器处理 |

`不可验证 ≠ 捏造`。一条无法抓取的引用（网络故障、付费墙）会被降级为 D1 质量问题；它**不会**触发 CF1。CF1 需要证据，外加人工确认，因为对竞品做出错误的捏造判定，是本框架可能犯下的最具破坏性的评分错误。

## 评分模式

- **确定性检查点**（类型见评分器）由脚本按任务容差与基准真值比较。无 LLM 判断。它们构成客观维度的**第一层基线**，每个未通过的检查点是一笔可追溯的扣减。
- 两次盲评评审对**全部六个维度**以扣分制打分（满分起评、逐条登记扣分项与证据），构成**第二层扣分锚点**；分歧超过一级则上报人工裁定。在客观维度（`objective_dims`）上，评审的扣分**仅限不可数值核验的质量缺陷**（见 §计分 的两层不重叠约束）——数值正确性已由第一层负责。
- 评分官对照扣分锚点做**绝对**评分——绝不与其他作品两两比较——这正是作品虽独立评分、跨作品对比仍公平的原因。长度不加分，也不因"短"扣分；只有被标记的缺陷才扣分。

## 附：任务规范容器的 tier 相干性约束（见 §5，由 spec-lint 强制）

见 `taskspecs/README.md` 与 `eval-taskspec-lint`。tier 描述任务的可核验程度，决定客观锚定能覆盖多少评分：
- **T1｜确定性**：`objective_dims == [D1, D2]`；有可执行数值真值；承重数值检查点都有真值路径。
- **T2｜半确定性**：`len(objective_dims) ≤ 1`；至少一条可核验路径（可执行真值 / 内部一致性 / 抽样核验）。
- **T3｜研判型**：`len(objective_dims) ≤ 1`；非客观（研判/引用主导）权重 ≥ 40。
- 全 tier：权重合计 100；`objective_dims ⊆ {D1, D2}`；D6 权重 ≥ 5；任何数值型检查点若非内部一致性类型，必须有真值路径（禁止伪确定性）。
