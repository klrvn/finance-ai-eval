# 评分宪法（Constitution）— 不可变原则层

> 这是评测框架的**第 1 层（宪法层）**。它定义所有任务共享的评分原则：六维度、扣分制、
> CF 规则、盲评与隔离纪律。**任何任务规范容器（第 2 层）都不得违反本层。** 容器只能在
> 下方「可参数化面」列出的范围内定制；越界项由 `eval-taskspec-lint` 拦截。
>
> 迁移说明：本文件由原 `skills/eval-task-specs/references/rubric_and_cf.md` 提升而来，内容不变，
> 并在开头增补「不可变原则 vs 可参数化面」的宪法框架。

## 0. 不可变原则（容器不得覆盖）

- **维度集**：恰好 D1-D6，定义如下表，不可增删、不可改名。
- **扣分词表与分值**：轻微 −0.5 / 明显 −1 / 严重 −2；`level = max(0, 4 − Σ扣分)`，允许 0.5 步长。
- **CF 规则**：CF1-CF5 的触发证据要求与封顶效果固定；CF1 的人工确认闸门不可绕过。
- **NA 不扣分**：不可核验（真值缺失/网络故障/付费墙）从分母剔除，绝不当作缺陷扣分。
- **不可验证 ≠ 捏造**：抓不到的引用是 D1 质量问题，不触发 CF1。
- **篇幅中性**：更长不加分，更短不扣分；只有被标记的缺陷才扣分。
- **盲评靠机制**：每轮盲评派发全新子代理，绝对（非两两比较）评分；作品之间互相隔离。
- **运算交给脚本**：确定性真值只能由可执行、带自检的计算器产出，绝不由模型估算。

## 1. 可参数化面（容器可在此范围内定制，且仅此范围）

| 参数 | 允许范围 | 校验者 |
|---|---|---|
| `rubric_weights` | 六维度整数权重，合计 100；D6 权重 ≥ 5；按 tier 相干性约束（见 §5） | spec-lint |
| `objective_dims` | `{D1, D2}` 的子集（含空集）——汇总器只对 D1/D2 做客观锚定 | spec-lint |
| `cf_rules` | `{CF1..CF5}` 的子集；阈值在宪法界限内（如 CF2 未引用率阈值 ∈ [0.15, 0.40]） | spec-lint / cf-auditor |
| `citation_policy` | `none` / `sample,k` / `per_cell_sample` / `full` | citation-verifier |
| `checkpoint_schema` 字段类型 | 只能取自 §4 的封闭类型表 | spec-lint / grader |
| `judge_notes` 扣分锚点 | 「情形 → 既有严重度」的映射；**禁止**出现期望数值答案、禁止改权重、禁止新增严重度 | spec-lint |
| `extraction_notes` | 纯格式/单位约定散文；不得改变 schema | — |
| 计算器 / 验证器插件 | 遵循计算器契约 / 验证器契约（见流程层文档） | spec-lint + 插件自测 |

**升级规则**：任何在 ≥2 个容器里以插件形式出现的能力，必须上升为共享库/引擎能力（否则引擎会被任务反向绑定）。

## 评分总原则：扣分制

所有作品在每个维度上**默认满分起评**。分数只能因**被明确标记的缺陷**而下降——每一笔扣分都必须落到一条具体的、有证据的问题记录上（未通过的检查点、未通过的引用核验、盲评扣分条目、CF 封顶）。由此推出三条纪律：

1. **无标记，不扣分。** 评分官不得因"感觉一般""还可以更好"这类无法落到具体缺陷上的印象降级；说不出具体问题就保持满分。
2. **不可核验 ≠ 缺陷。** 因基准真值缺失、网络故障、付费墙而无法核验的项（NA）不扣分，从分母剔除并单独披露。
3. **每笔扣分可追溯。** 报告中每个非满分的维度都必须能展开成"扣了多少、为什么扣、证据在哪"的清单。

## 评分维度（满分 100 分，权重按任务设定）

| 维度 | 维度名称 | 度量内容 |
|---|---|---|
| D1 | 数据完整性与依据（grounding） | 使用的是真实数据（而非训练记忆）；数值在容差内匹配基准真值；每条量化主张都有引用；未编造标的代码/日期/来源 |
| D2 | 方法正确性 | 正确的公式、框架、惯例（计息天数、年化、基准、归因模型） |
| D3 | 完整性 | 所有必需交付物均已呈现**且经计算**（而非仅被描述） |
| D4 | 分析质量与洞察 | 推理深度；正确的驱动因素/风险；连贯、非套话的论点 |
| D5 | 可操作性与适配性 | 具体、可直接用于决策且附理由的建议；契合所声明的用户/风险画像 |
| D6 | 外部工具链完整度 | 数据获取与计算是否经由恰当、完整的外部工具链完成：金融专用数据 API/终端/专业计算库 > 通用结构化数据源 > 野网页抓取/搜索摘要 > 无工具（凭记忆给数）；计算是否经代码/工具执行且有可查轨迹 |

## 扣分量尺（按维度）

每个维度从 **4 分（优秀）起评**。盲评评分官逐条登记扣分项，每项必须带严重度判定与证据引用：

| 严重度 | 扣分 | 判定标准 |
|---|---|---|
| 轻微（minor） | −0.5 | 不影响结论的小缺陷（个别引用无日期、次要字段呈现不当、单个非关键数据点来源层级偏低） |
| 明显（major） | −1 | 影响该维度可信度的缺陷（一处关键假设无依据、一类交付物质量不达标、关键数据走了明显更差的来源） |
| 严重（severe） | −2 | 使该维度大面积失效的缺陷（核心方法用错、关键交付物缺失、关键数据完全凭记忆给出） |

维度等级 = `max(0, 4 − 扣分合计)`，允许 0.5 步长。等级语义与旧量尺向后兼容：

| 等级 | 标签 | 扣分制下的含义 |
|---|---|---|
| 4 | 优秀（Excellent） | 未发现任何可扣分问题 |
| 3 | 良好（Good） | 仅有轻微问题（合计扣 1 分） |
| 2 | 合格（Adequate） | 存在明显缺陷（合计扣 2 分） |
| 1 | 较差（Poor） | 多处明显缺陷或一处严重缺陷叠加轻微问题 |
| 0 | 不及格（Fail） | 缺陷合计 ≥4 分：缺失，或以误导性的方式出错 |

**计分**：`weighted_points = fraction × weight`。
- 主观维度 `fraction = level/4`，`level` 为两位评分官各自扣分后等级的均值。
- 客观维度**天然就是扣分制**：`fraction` 从 1.0 起步，每个未通过的检查点按其在分母中的份额扣减；NA 检查点从分母剔除（不扣分）。比例保持**连续**（不先四舍五入到整数等级，避免同类作品因 0.01 的通过率差落到不同等级、以及 Python 银行家舍入造成的不一致）。

`objective_dims`（按任务）：汇总器根据实测数值（而非评分官意见）设定这些维度：
- **D1** 客观 `fraction = grounding_objective`：将引用的已核验占比（当存在引用策略时权重 0.6）与 `grounding:true` 检查点的通过率（权重 0.4；若无引用策略则取全部权重）相混合。每个未通过的 grounding 检查点 / 未核验通过的引用就是一笔有名有姓的扣分。
- **D2** 客观 `fraction = methodology_pass_fraction`（`methodology:true` 检查点的通过率）；若任务未标注任何 `methodology` 字段，则回退到全部检查点的 `pass_fraction`。

不在 `objective_dims` 中的维度取两位评分官扣分后等级的均值。若两位评分官在任一维度上分歧超过一级，该维度被标记 `needs_review`（仍按均值计分，但提交人工裁定）。

**有效分母**：扣分制的"默认满分"以**该维度实际接受了审查**为前提。若某维度既无客观指标又无评分官等级，它既不默认满分、也不被扣分——其权重从分母剔除并披露：汇总器输出 `scored_weight`、`unscored_dims` 与归一化分 `score_normalized`，以免部分评分被误读为满分制。

## D6 外部工具链完整度：来源层级与扣分锚点

D6 评的是**工具使用行为**：作品是否用对了外部工具链来获取数据、执行计算。证据来自作品自带的工具/执行轨迹与提取器登记的 `tool_inventory`；评分官只认作品内可见的证据，不脑补。

**来源层级（tier ladder）**：

| 层级 | 说明 | 示例 |
|---|---|---|
| A | 金融专用数据 API / 终端 / 专业计算库 | Wind、Bloomberg、Refinitiv、tushare、AkShare、交易所或官方行情接口；QuantLib、实际执行的回测/定价代码 |
| B | 通用结构化数据源 | 统计局/央行官方 API、基金公司或发行人官网披露页、通用行情 API |
| C | 野网页抓取 / 搜索摘要 | 任意第三方网站正文、搜索引擎片段、聚合站转载数据 |
| D | 无工具 | 数字直接来自模型记忆，无任何获取或执行轨迹 |

**D6 扣分锚点（从 4 起评，对号入座、逐条登记）**：

| 情形 | 扣分 |
|---|---|
| 关键数据取自 C 层，而该数据显然有 A/B 层来源可用 | −1 |
| 关键数据无任何工具来源（D 层，凭记忆给数） | −2 |
| 宣称的计算未经代码/工具执行（无执行轨迹，亦无可复现产物） | −1 |
| 工具链覆盖不完整：部分关键步骤有工具、其余关键步骤没有 | −0.5 ~ −1 |
| 工具调用失败后未处理/未换源，直接使用降级或缺失的数据 | −0.5 |
| 非关键数据点取自 C/D 层 | −0.5 |

判定"关键数据"以任务的 `measurable_outputs` 与承重量化主张为准。各任务家族"什么算 A 层"由容器 `judge_notes.md` 声明（例如债券定价：A 层 = QuantLib/终端；行情回测：A 层 = 交易所/Wind/tushare 接口 + 实际执行的回测代码）。同一事实缺陷若已触发 CF3（只描述不计算）封顶 D2/D3，D6 仍可就"无执行工具链"独立扣分——D6 评工具使用行为，D2/D3 评结果，二者不算重复惩罚。

## 关键失败规则（打分后应用）

CF 封顶是扣分制的极端形态：证据确凿的结构性缺陷直接把维度或总分压到上限。

| 规则 | 触发条件 | 所需证据 | 效果 |
|---|---|---|---|
| CF1 | 将捏造的数据当作真实呈现（编造的价格/指标/持仓/标的代码/来源/引文片段） | **确凿**证据：一个不存在的标识符，或一个说法不同的被引来源。提议给人工，不自动应用 | 总分封顶为 30；运行被标记 |
| CF2 | 有相当比例的量化主张未给出引用 | 引用审计中未引用主张占比超过阈值 | D1 封顶为等级 1 |
| CF3 | 描述了分析但未产出计算结果 | 无执行轨迹**且**无内容能复现所宣称指标的产物 | D2 与 D3 封顶为等级 1 |
| CF4 | 未实际获取便把一个明显陈旧的数字当作当前使用 | 数值与所提供的快照不一致 / 明显早于截止点 | D1 封顶为等级 1 |
| CF5 | 某个确定性检查点超出容差 | 检查点评分器的偏差超过 `tol` | 该检查点记 0 分（不给部分分）；由评分器处理 |

`不可验证 ≠ 捏造`。一条无法抓取的引用（网络故障、付费墙）会被降级为 D1 质量问题；它**不会**触发 CF1。CF1 需要证据，外加人工确认，因为对竞品做出错误的捏造判定，是本框架可能犯下的最具破坏性的评分错误。

## 评分模式

- **确定性检查点**（类型见评分器）由脚本按任务容差与基准真值比较。无 LLM 判断。每个未通过的检查点是一笔可追溯的扣分。
- 不在 `objective_dims` 覆盖范围内的**量规维度**，由两次盲评评审以扣分制打分（满分起评、逐条登记扣分项与证据）；分歧超过一级则上报人工裁定。
- 评分官对照扣分锚点做**绝对**评分——绝不与其他作品两两比较——这正是作品虽独立评分、跨作品对比仍公平的原因。长度不加分，也不因"短"扣分；只有被标记的缺陷才扣分。

## 附：任务规范容器的 tier 相干性约束（见 §5，由 spec-lint 强制）

见 `taskspecs/README.md` 与 `eval-taskspec-lint`。tier 描述任务的可核验程度，决定客观锚定能覆盖多少评分：
- **T1｜确定性**：`objective_dims == [D1, D2]`；有可执行数值真值；承重数值检查点都有真值路径。
- **T2｜半确定性**：`len(objective_dims) ≤ 1`；至少一条可核验路径（可执行真值 / 内部一致性 / 抽样核验）。
- **T3｜研判型**：`len(objective_dims) ≤ 1`；非客观（研判/引用主导）权重 ≥ 40。
- 全 tier：权重合计 100；`objective_dims ⊆ {D1, D2}`；D6 权重 ≥ 5；任何数值型检查点若非内部一致性类型，必须有真值路径（禁止伪确定性）。
